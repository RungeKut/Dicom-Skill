# Шаги осей объёма при MPR

**Что происходит:** объём vol[z,y,x] собирается из серии: шаг по z = разница
pos соседних срезов, в плоскости — PixelSpacing; даунсемплинг в плоскости
меняет только xy. Если держать одну функцию «мм→индекс» на все оси (частая
ошибка после даунсемпла), все кропы, метки сеток и «найденные» координаты
по z уезжают кратно (в практике — вдвое): прицельные панели показывают
чужие уровни, структуры «теряются», разбор уходит в длинный поиск.

**Как правильно:** sp_z и sp_xy хранить раздельно; индекс по каждой оси =
мм / шаг_этой_оси; на самодельных панелях сетку рисовать с шагом оси
(изображение часто анизотропно по осям — grid_panel это не отслеживает).
Проверка масштаба — по анатомическому ориентиру (вертebrae/глазницы) или
численному лэндмарку, не по внешнему виду.

**Как неправильно:** `i(v) = v/шаг_в_плоскости` для всех осей; подписывать
панели «мм», посчитанными по чужому шагу; доверять «найденной» структуре,
пока масштаб не подтверждён.

**Чем подтверждено:** КЛКТ с шагом z 0.2 мм: панели с сеткой «z=90 мм»
показывали уровень 45 мм; после разделения шагов оба сустава
локализовались с первого прохода.
